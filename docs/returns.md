# 반품등록

`CLAUDE.md`에서 분리한 상세 문서. 내용은 그대로이고 위치만 옮겼다.

## 🤖 자동 반품등록 (2026-09-30 영업2팀 — "사입출고등록처럼 반품건이 있다면 등록")
- 반품등록 탭 맨 위 `#retAutoBox`. 버튼 🛍 홈쇼핑 반품등록(`hr`) · 🛒 코스트코 반품등록(`cr`), 각각 🔍 미리보기 → ✅ 이대로 등록.
  색은 사입출고 자동 매출등록과 같다(평소·완료 청록 `#1b6e82`, 요망 보라 + 건수, 진행 중 하늘).
- **진행 막대**(2026-10-07 영업2팀): 카드(`_retCard`, 자동화 탭 포함)에 사입출고와 같은 `_saipProgBar` + `▸ 지금 단계`·오류 줄.
  단계는 `SAIP_STAGES.ret` — 시작 · 반품리스트 읽기 · 플레이엠디에 이미 있는지 확인(30~40초, 가장 김) · 불러오기 · 저장 · 저장 확인 · 불량 창고간이동·시트 정리 · 마무리
  (`playmd-return.mjs` 로그 문구에 맞춘 정규식 — 문구를 바꾸면 같이 고칠 것). 저장 두 단계는 미리보기에서 뺀다.
- **등록할 줄 = 1단계 불러오기와 같은 규칙**(`_retCollect`): 홈쇼핑 탭은 `_hsrSheetKeep` → `_hsrMapRows`, 온라인 탭은 `_ccrMapRow`(코스트코만) → `_ccrMatchRow`,
  그중 처리완료 + 입고일·처리일·해체일. 표(`hsrRows`/`ccrRows`)·공유본은 건드리지 않는다.
  1단계·붙여넣기도 이 함수들을 쓴다(떼어낸 것일 뿐 규칙은 그대로).
- **줄 열쇠** = `입고일|주문번호|상품명(공백 뺌)`의 짧은 해시(`_retFnv`), 같은 줄이 또 있으면 `-2`… 팀 공유 등록 기록 `ws/retLog`
  (`{hr:{열쇠:{at,by,d,q,c,p,s}},cr}`, s = saved·savecheck·found)에 있으면 **다시 올리지 않는다** — 시트 정리(온라인(완료)로 옮기기)는 사람이 해서
  등록한 줄이 시트에 남아 있을 수 있다. 카드에 `📝 시트 정리 필요 N건`으로 알린다. 200일 지난 기록은 자동화가 정리한다.
- 요망 여부는 **이 화면을 연 사람의 브라우저가** 시트를 직접 읽어 센다(`_retScan`, 탭 열 때 + 5분마다 — 반품등록 화면이나 🤖 자동화 탭이 열려 있을 때, 2026-10-07 예전 10분). 자동화 PC의 `saip-ready`와는 따로다.
- 요청은 사입출고와 같은 `ws/saipReq[hr|cr]`(날짜 없음, `expect` = 미리보기 때 줄 열쇠 묶음) → `automation/saip-watch.mjs` →
  `playmd-return.mjs --kind --save --by --expect`. 결과 `ws/hrRetStatus`·`ws/crRetStatus`(status: preview·saved·savecheck·none·allfound·partial·unmatched·changed·error).
- `playmd-return.mjs` 순서: 자비스에서 `_retCollect` → 기록에 있는 줄 빼기 → 코드·공급가가 빈 줄은 **반품등록 표(ws/hsrShare·ccrShare)에 사람이 채운 값**을 가져옴
  → 하나라도 비면 멈춤 → 매장출고반품현황(xpro6030q)을 **달마다** 조회해 같은 입고일·매장·상품의 사입반품(`SGREPGID=xpro4710a`, 음수)이 있으면
  수량까지 다 있으면 뺌(`found`, 저장 때 기록) · 일부만 있으면 멈춤 → 사입반품양식(`_retBuildXlsx`, 4단계 다운로드와 같은 7칸) →
  xpro4710a **작업구분 사입반품(라디오 값 2) · 공급가입력 · 시트명 사입반품양식** 불러오기 → 줄 수·값 대조 → 저장 → 다시 조회해 늘어난 수량 확인.
  **조회 결과가 비면 '중복 없음'으로 넘기지 않고 멈춘다**(두 달을 한 번에 조회하면 표가 15초 넘게 비어 있었다).
- **불량 창고간이동도 자동**(2026-09-30 영업2팀): 불량(물류답변 TRUE — 코스트코는 `_ccrMapRow`, 홈쇼핑은 머리글 `불량` 칸) 줄은
  반품 저장이 **확인(saved)되면** 같은 실행에서 [EX]창고입고반품이동등록(xpro1700a)에 작업구분 `[M] 창고간이동` · 파일형태 `[B] 바코드`
  (ui-select라 `pickUiSelect`로 고른다)로 NH → `BAD`(6단계 입고창고 칸) 이동을 올린다. 양식은 `_retBuildMoveXlsx`(6단계 다운로드와 같은 8칸, 비고 `코스트코 불량 반품`/`홈쇼핑 불량 반품`).
  창고간이동현황(xpro6600q, `PINRDT`·`PINRWCD`→`PINRCST`·`PINRGODCD+PINRCR`·`TOTQT`)으로 이미 옮긴 게 있으면 빼고(일부만이면 멈춤), 저장 뒤 늘어난 수량을 확인한다.
  retLog 줄에 `b:true, w:보내는창고`, 이동 뒤 `mv:{at,s:'moved'|'movecheck'|'found'}`. 반품은 저장됐는데 `mv`가 moved·found가 아니면 **다음 실행 때 이동만 다시** 한다
  (버튼이 요망, 카드에 `불량 창고간이동 대기 N건`). 반품 저장이 확인 안 되면(savecheck) 이동은 미룬다. 미리보기는 이동도 불러오기까지만.
  시험: `node playmd-return.mjs --kind=cr --test-move=YYYYMMDD:코드:수량` — 이동 불러오기까지만(저장·기록·알림 없음, `--save`와 같이 못 씀).
- **시트 정리도 자동**(2026-09-30 영업2팀): 코스트코 = `온라인` → `온라인(완료)` 맨 아래로 옮기고 **회색 음영**, `온라인`에서 삭제 ·
  홈쇼핑 = `홈쇼핑` → `온라인(완료)` 맨 아래로 옮기고 `홈쇼핑`에서 삭제(음영 없음). 세 탭 칸 배치가 같아 줄을 그대로 복사한다.
  **붙이는 자리 = 글자가 있는 마지막 줄 다음**(`lastDataRow_`, 2026-10-02): `getLastRow()`는 비어 있어도 드롭다운·서식이 깔린 줄까지 세어
  온라인(완료) 14579행 다음이 아니라 15395행 다음에 붙었다 → 앞 8칸 중 하나라도 글자가 있는 마지막 줄을 찾는다(회색 음영 찾기 `shade_`도 같은 기준).
  Apps Script는 자동화가 배포할 수 없어 **영업2팀이 script.google.com에서 코드를 바꾸고 '새 버전'으로 다시 배포**해야 적용된다(주소는 그대로).
  시트를 고치는 건 **사용자가 배포한 Apps Script 웹 앱**(`automation/sheet-cleanup.gs`, script.google.com 단독 프로젝트 — CX팀 시트에 스크립트를 붙이지 않는다)이 한다.
  자동화는 `automation/sheet-cleanup.json`({url, token} — 이 PC에만, 저장소에 올리지 말 것)으로 줄 내용(입고일 M/D · 상품명 · 주문번호)만 보낸다.
  웹 앱은 줄을 **내용으로** 찾고(A열 처리완료 · B열 입고일 · 상품명 칸 · 주문번호 칸), 복사가 원본과 같은지 확인한 뒤에만,
  지우기 직전에 줄이 그대로인지 다시 보고 아래 줄부터 지운다(바뀌었으면 멈춤). 음영 색은 온라인(완료) E열 최근 300줄에서 가장 많이 쓴 회색(없으면 `#d9d9d9`).
  대상 = retLog가 saved·found이고 `sh`(옮긴 시각)가 없는 줄. 옮기면 `sh`를 남긴다(삭제가 도중에 멈춰도 다시 복사하지 않음 → 카드에 `직접 지워 주세요`).
  미리보기는 dry-run(찾기만). 설정 파일이 없으면 `off`로 알리고 건너뛴다. 줄이 남아 있으면 버튼이 요망이고 누르면 정리만 한다(`cleanonly`).
- 플레이엠디 반품 줄 모양(2026-09-30 확인): 비고 `코스트코 반품`/`홈쇼핑 반품`, 반품일자 = 입고일, 창고 NH, 불러온 표 `PXLSQT`는 양수.

- **두 반품등록 표는 팀 공유다**(`ws/ccrShare`·`ws/hsrShare`, 2026-09-23 영업2팀) — 한 사람이 `시트에서 바로 불러오기`를 누르면
  **접속한 모두가 같은 표**를 본다. 표를 다시 그릴 때마다 올리되 **내용이 그대로면 올리지 않는다**(원격으로 받아 그린 것이 되돌아 올라가면 무한히 오간다).
  날짜(`in`·`proc`·`open`)는 Date라 JSON을 거치면 글자가 되므로 받을 때 되돌린다(`_retReviveRows`).
  **표에서 입력 중이면(포커스가 표 안) 다시 그리지 않는다** — 치던 값이 날아가지 않게.
  수취인·연락처·주소는 애초에 읽지 않으므로 공유본에도 없다.

- 반품등록 탭에는 **홈쇼핑 반품등록**과 **코스트코 반품등록** 두 섹션이 있고, 둘 다 4단계다
  (1 반품리스트 열기 · 2 붙여넣기 · 3 코드매칭 · 4 사입반품양식 다운로드).
  1단계 링크는 같은 시트의 다른 탭을 연다 — 홈쇼핑은 `gid=36451127`, 코스트코는 `gid=0`(온라인).
  코스트코 1단계 안내는 **온라인 탭에서 `처리완료·입고일·처리일·해체일`이 모두 적힌 내역을
  `온라인(완료)` 시트로 옮긴 뒤 2단계에 붙여넣으라**고 적어 둔다.
  **색(초록/연두) 이야기는 안내에서 뺐다**(2026-09-23) — 등록 조건에서 음영을 뺐는데 안내에만 남아 있으면 헷갈린다.
  홈쇼핑 쪽에는 **5단계 시트 정리** 안내가 더 있다 —
  ① 홈쇼핑 → `온라인(완료)`에 해당 건 복사 후 홈쇼핑에서 삭제 ② 불량건은 창고간 이동
  ③ **세일즈매니지먼트에 반품 데이터 업로드**(바로가기 `https://wssales.pages.dev/#data` — 코스트코 7단계 ④도 같다).
  세일즈매니지먼트는 탭을 바꿔도 주소가 안 바뀌고 주소로 탭을 고르지도 않아서, **`#data`는 그쪽이 주소의 `#탭이름`을 읽도록 고쳐야 먹힌다**
  (그 전에는 대시보드가 열릴 뿐 문제는 없다). 그쪽 `setTab` 바인딩 뒤에 `location.hash`를 읽어 `setTab(t)` 하는 몇 줄이면 된다.
  **1단계 `📥 시트에서 바로 불러오기`**(2026-09 영업2팀, `hsrLoadSheet`/`ccrLoadSheet`/`_retSheetRows`): 반품리스트 시트
  (`RET_SHEET_ID`, 홈쇼핑 `gid=36451127` · 온라인 `gid=0`)가 **링크 공유(보기)** 라 gviz CSV(`/gviz/tq?tqx=out:csv&gid=`)를
  브라우저에서 바로 읽는다(CORS 허용). 읽자마자 **수취인·연락처·주소 열을 비우고**, 칸 안의 줄바꿈·탭을 지워
  붙여넣기와 같은 경로(`_hsrProcessRows` / `ccrPasteRows`)로 넘긴다 — 파싱 규칙이 하나로 유지된다.
  불러오기는 **표를 비우고 새로** 채운다(두 번 눌러도 중복 안 됨, 표에 행이 있으면 확인).
  **홈쇼핑 탭도 `결과 = 처리완료` + 입고일·처리일·해체일이 모두 적힌 줄만** 불러온다(2026-09-18 영업2팀 지정, 머리글로 열을 찾음).
  제외 사유별 건수(결과 빈칸·처리보류·해체일 없음 …)를 버튼 아래에 적는다. **붙여넣기도 같은 조건**(`_hsrReady`/`_hsrWhyNot`) — 머리글이 있으면 `결과`·`처리일` 칸도 읽고(`결과`가 두 번 나오면 첫 칸),
  머리글이 없으면 `_ccrMapRow`의 status·proc를 쓴다. 붙여넣은 표에 결과 칸이 아예 없으면 상태는 안 보고 날짜 3개만 본다.
  조건 미충족 줄은 회색 + 툴팁에 이유.
  온라인 탭은 모든 온라인몰 반품이 섞여 있어 **쇼핑몰에 `코스트코`가 든 · 상태 `처리완료`** 인 줄만 가져온다
  (수동 흐름의 '초록색 처리완료 건'과 같은 기준 — 셀 색은 CSV로 못 읽는다).
  시트를 비공개로 바꾸면 gviz가 로그인 HTML을 돌려주므로 그때는 안내 알림을 띄운다 → 그 경우 Apps Script 웹앱으로 바꿔야 한다.
  코스트코 쪽은 CX팀_반품리스트(구글 시트) **`온라인` 탭**에서 `처리상태 ~ 결제가`(15열)를 그대로 붙여넣는다
  **열 위치는 고정하지 않고 내용으로 찾는다**(`_ccrMapRow`) — 복사 범위가 한 칸만 밀려도
  고정 위치로는 상품명 자리가 어긋나 전부 미매칭이 됐다.
  상품명은 **점수로 고른다** — `화이트샌즈`가 든 칸 중 `[`로 시작하고 바로 뒤가 수량(작은 숫자)인 칸이 이긴다.
  가장 긴 칸을 쓰면 `333165084-1 #694099-BK 화이트샌즈 … 합포장하셨다며 전달 요청` 같은 **비고 칸**을 집어
  상품명이 통째로 어긋난다(`#`·`합포장`·`요청`·주문번호가 든 칸은 감점).
  수량·결제가는 상품명 뒤 첫 숫자칸과 다음 칸,
  상태는 `CCR_STATES` 중 하나가 든 칸, 날짜는 상품명 앞의 날짜칸들(마지막이 해체일)에서 찾는다.
  **`처리보류`·`확인요청`·`출고예정`은 제외**한다(`CCR_SKIP`) — 아직 끝난 건이 아니다.
  상품명 → 상품컬러코드는 `_hsFindMatchFromDefaultData`로 찾고, 공급가 = 결제가 ÷ 수량.
  결제가가 `미매핑`처럼 숫자가 아니면 비워 두고 표에서 직접 채운다.
  **반품일자 = 물류입고일**(매뉴얼 `반품 입력_이미지 매뉴얼` 기준), 매장·창고코드는 4단계 입력칸(기본 `COSO`/`NH`).
  **등록 조건 = 처리완료 + 입고일·처리일·해체일 모두**(2026-09-23 영업2팀 — **민트색 음영은 빼기로 했다**)(2026-09-18 영업2팀 재지정, `_ccrReady`/`_ccrWhyNot`) —
  하나라도 빠지면 회색으로 두고 빼며 줄 툴팁에 이유를 적는다. 정렬·반품일자는 여전히 물류입고일(`_ccrSortByIn`).
  (한때 '입고일만 있으면 등록'으로 풀었다가 되돌렸다 — 해체일까지 끝난 건만 등록한다.)
  **민트색 음영은 더 이상 보지 않는다**(2026-09-23 영업2팀) — 셀 색은 Sheets API가 켜져 있어야 읽히는데 실제로는 403으로 못 읽는 때가 많았다.
