# 창고재고 · 재고확인 · 재고이관

`CLAUDE.md`에서 분리한 상세 문서. 내용은 그대로이고 위치만 옮겼다.

- **창고재고현황은 한 곳에만 올리면 세 곳 모두 반영된다**(`whShareFile`, 2026-09 영업2팀) — 발주 공용(`whLoadFileOnly`) ·
  백화점몰 재고확인(`_onsProcessWhFileOnly`) · 홈쇼핑몰 재고확인(`_stockProcessWhFileOnly(file,true)`)에 같은 파일을 넣고,
  홈쇼핑몰은 `재고 확인 시작`(`startStockCheck`)까지 자동으로 돌린다. 세 입구 함수(`whLoadFile`·`_onsProcessWhFile`·`_stockProcessWhFile`)는 모두 `whShareFile`로 모인다.
  플레이엠디에서 받을 때는 **창고명을 비우고 전체 창고**로 조회해 셀 병합 해제로 받는다(2026-09-18 변경 — 코스트코 재고확인에 [CSTC]가 필요).
  전체 파일이어도 발주·홈쇼핑몰(`_stockWhRows`)·백화점몰(`_onsWhRows`)은 **주희물류만** 쓴다(`_whIsShip`·`_whShipFilter`: 창고코드 `NH\d*`·이름 `주희물류`, 불량·샘플 제외).
  이 필터 없이 전체 파일을 넣으면 창고를 전부 더해 재고가 부풀려진다. 발주 공용 `whStock`은 원래 ship/all을 나눠 둔다.
  전체 파일은 약 8,400줄 → `whRaw` 약 750KB(localStorage·Firebase 모두 괜찮은 크기).

- **코스트코 재고확인** (`📦 재고확인` → `🛒 코스트코 재고확인`, `page-ccstock`, 2026-09 영업2팀): 코스트코 탭 상품·색상(`costcoDB.products`,
  진열 순서 `CC_PROD_ORDER`, 같은 코스트코 코드의 `바르셀 직매입`은 한 번만)을 **발주 매칭표(`CC_PDF_CODE_MAP`)로 자사 상품코드**에 잇고,
  창고재고현황의 **[CSTC] 코스트코 창고**와 **[NH] 주희물류** 재고를 상품코드·칼라별로 모아(`_ccsFromRows`, `_whApplyRows`에서 호출, 메모리 `ccsWh`)
  색상명 핵심(`_onsColorCore`)으로 맞춘다(`_ccsColor`). 창고에 그 색 줄이 아예 없으면 상품데이터에서 색상코드를 찾아 **재고 0**으로 본다.
  **몰 상태는 파일이 없어 화면에서 눌러 둔다**(판매중 ↔ 몰 품절, 팀 공유 `ccsMallDB` / `ws/ccsMall`, 키 `코스트코코드|색상명`).
  할 일 세 목록: ⛔ 품절 처리 필요(판매중 + CSTC < 기준) · ✅ 품절 해제 가능(몰 품절 + CSTC ≥ 기준) · 📦 CSTC 보충 필요(CSTC < 기준 → NH 재고, `WH_MIN_ORDER` 10개 이하는 보충 불가).
  기준은 `ccsOutMin`(기본 30, localStorage). 목록의 `✔ 품절 완료`/`✔ 해제 완료`는 몰 상태를 바꾼다.
  매칭표에 없는 상품(`우양산 2종`·`센토`·`해피트리`)은 `발주 매칭표에 코드 없음`으로, 코스트코 탭에 없는 CSTC 재고는 표 아래에 따로 적는다.

- **창고재고는 이제 팀 공유다** — 필요한 열만 남긴 원본(`_whCompact`: 1행 재고일자 문구 + 머리글 + 데이터, 약 230KB)을
  `whRaw`(`ws/whRaw`)에 올리고, 받는 쪽은 `_whApplyRows(rows,fileName,owner)`로 발주 공용(`whLoadRows`)·
  백화점몰(`_onsWhRows`)·홈쇼핑몰(`_stockWhRows`)·재고이관(`_tfWhFromRows`)에 같은 행을 넣는다.
  **owner(올린 브라우저)만** 백화점몰 대조 결과 저장과 홈쇼핑몰 `재고 확인 시작`을 한다 — 다른 PC는 화면만 맞추고
  결과는 팀 공유본을 받는다(안 그러면 PC마다 결과를 덮어쓴다). `_whRawApplied`(at)로 같은 자료를 두 번 적용하지 않고,
  새로고침하면 localStorage `whRaw`로 다시 채운다(홈쇼핑몰 `stockWarehouseRows`는 메모리 전용이라).
  재고이관 분석이 쓰는 `상품명·품목·TAG가` 열도 남긴다(`WH_KEEP_COLS`).

- 창고재고 (발주 공용 · `whStock`): PlayMD `출고관리 > 현황 > 창고재고현황` 엑셀을 한 번 올리면
  **발주 화면 여섯 곳**(발주서 변환 · 수기발주 · 코스트코 발주 · 아난티 발주 · CX팀 물류센터 · 사입출고등록)의
  표에 `창고재고` 열이 뜨고 발주 가능 여부가 보인다. 업로드 칸은 `.wh-slot` 자리에 `whInitSlots()`가 채워 넣고,
  어디서 올리든 같은 자료를 쓴다(끌어오기는 문서 한 곳에서 위임 처리).
  **`.wh-slot`을 업로드 후에만 보이는 영역 안에 두지 말 것** — 아난티는 `anInfoBar`(발주서 올리기 전 `display:none`) 안에 있어
  창고재고 칸이 아예 안 보였다. 지금은 단계 카드 아래 독립 블록으로 둔다.
  **기본 기준은 주희물류(NH·NH3)**다 — 전체를 더하면 불량창고·생산팀·타팀·샘플 창고까지 잡혀
  실제 출고 가능량보다 훨씬 많아 보인다(전체 3,472품목 vs 주희물류 2,667품목).
  화면에서 `전체 창고 기준`으로 바꿀 수 있고 선택은 브라우저에 남는다.
  창고 파일은 `상품코드+칼라코드` 단위라 자사코드에서 **사이즈 한 글자를 떼고** 맞춘다(재고확인 탭과 같은 규칙).
  **창고재고 10개 이하는 발주 불가**다(`WH_MIN_ORDER`, 2026-09 영업2팀 지정 — 10개는 발주 안 함) — `N (발주불가)`로 빨갛게 적는다.
  11개 이상인데 주문 수량보다 적으면 `부족 N`, 주문 수량의 2배 미만이면 주황으로 표시하고,
  창고재고현황에 없는 코드는 `?`로 둔다.
  (예전엔 팀 공유를 안 했지만 지금은 `whRaw`로 공유한다 — 위 `홈 PlayMD 자료 업로드` 참고.)

- 재고확인 (`📦 재고확인` 드롭다운) — `🏬 백화점몰 재고확인`·`🏭 홈쇼핑몰 재고확인`·`🛒 코스트코 재고확인` 세 탭을 묶어 둔다.
  세 탭 모두 머리에 **`▶ 재고 확인` 버튼**(`stockTodoGo(kind)`, 2026-09 영업2팀)이 있다 — 누르면 최신 창고재고로 다시 계산하고
  **할 일 목록으로 스크롤해 노란 테두리로 잠깐 강조**하며, 버튼 옆에 `품절 처리 N건 · 해제 가능 N건`(코스트코는 보충 건수까지)을 적는다.
  자료가 없으면 무엇이 빠졌는지 그 자리에 빨갛게 적는다(창고재고 없음 · 백화점몰 상품리스트 없음 · CSTC 창고 없음).
  홈쇼핑몰은 예전 `▶ 재고 확인 시작` 버튼이 이 동작을 겸한다(`startStockCheck` 뒤 목록으로 이동).

- 홈쇼핑몰 재고확인 — **상품리스트는 올려서 팀 공유로 쓴다**(2026-09 영업2팀, `📤 상품리스트 업데이트` → `hsListUpload`).
  올린 게 있으면 `hsProdListDB`(`ws/hsProdList`, `{rows,at,by,fileName}`)를 쓰고, 없으면 예전처럼 저장소의 `홈쇼핑상품리스트.xlsx`를 읽는다
  (`loadHsProductList`). 파싱은 업로드·기본 파일 모두 `_hsParseProductList` 하나로 — 자사코드 칸(영문+숫자)을 찾아 상대 위치로 채널·상품명·칼라명·품절표시·URL을 읽는다.
  바꾸기 전에 건수를 보여주고 확인받으며(팀 전체가 쓰는 자료), 올린 뒤 창고재고가 있으면 `startStockCheck`까지 바로 돌린다.
  머리에 `상품리스트 9/21 08:27 업데이트 · 187색 (올린 사람)` 또는 `기본 상품리스트 사용 중`을 적는다(`_hsListMsgRefresh`).

- 홈쇼핑몰 재고확인: 결과를 **채널 → 상품**으로 묶고, 상품마다 **카드**로 만들어
  `grid-template-columns:repeat(auto-fill,minmax(320px,1fr))`로 한 줄에 여러 개를 깐다
  (1,400px 폭에서 4열). 표로 늘어놓으면 좌우가 넓어 읽기 나빴다.
  카드 머리에 상품명·색상 수·품절 수, 안쪽에 `칼라 · 재고 · 품절` 줄. 자사코드는 줄 툴팁으로만 둔다.
  채널 안에서는 **품절 많은 상품 → 재고 적은 상품** 순으로 정렬한다.
  **창고재고가 `품절 기준`(기본 30개)보다 적으면 품절로 본다**(`hsOutMin`, 화면에서 조정·localStorage 저장) —
  몇 개 안 남은 컬러는 몰에 걸어둬도 곧 결품이라 품절로 취급한다.
  맨 위에 **할 일 두 목록**을 띄운다 — 상품리스트의 `품절표시`(note)는 몰에 지금 걸린 상태,
  `qty`는 창고재고다. `✅ 품절 해제 가능`(몰 품절 + 창고재고 기준 이상)과
  `⛔ 품절 처리 필요`(몰 판매중 + 창고재고 기준 미만).
  — 해야 할 일이 필터에 가려지면 안 되므로.
  **완료 체크**(2026-09 영업2팀, 팀 공유 `ws/hsStockMarks` = `hsStockMarks`): 목록 줄마다 `✔ 품절 완료`/`✔ 해제 완료`를 누르면
  그 색을 몰 품절/몰 판매중으로 보고(`_hsMallOut`) 목록에서 뺀다(`c[채널|자사코드]={st,note}`).
  카드의 `전체 품절`은 상품을 통째로 내린 경우(나바르처럼 코랄 하나만 남아 전체 품절) — 모든 색을 몰 품절로 보고
  **해제 가능 목록에도 올리지 않는다**(`p[채널|상품명]={sig}`, 카드는 흐리게 + `🔒 전체 품절 처리됨`).
  **체크는 상품리스트의 품절표시가 바뀌면 저절로 풀린다** — 체크할 때의 품절표시(`note`, 상품은 전 색상의 서명 `sig`)와 다르면 무시하고,
  저장할 때 풀린 체크는 지운다(`_hsSaveMarks`). 색상 줄의 `몰품절✔`/`몰판매✔`를 누르면 체크가 풀리고, 안내줄에서 전체 지우기.
  버튼은 상품명 대신 `stockCheckResults`의 **순번**을 넘긴다 — 이름에 따옴표가 있으면 onclick이 깨진다.

- 백화점몰 재고확인: 롯데 파트너오피스 **단품 재고관리 → ExcelExport** — 화면에서는 **`백화점몰 상품리스트`**라고 부른다
  (몰에 걸린 상품과 판매상태가 들어 있는 기준 자료라 팀 공유로 저장되고, **매장 추가·몰 상품 변경 때만** 올린다. 평소엔 창고재고만 올린다)
  (`온라인 재고`·`스타일코드`·`옵션` 열)를 올리면 채널상품별 백화점몰 재고를 본다.
  스타일코드는 채널 접미사가 붙어 오므로(`WCFM100L_LT` → `WCFM100L`) `_` 앞만 쓰고,
  옵션 `그레이/free`에서 색상만 떼어 상품데이터와 맞춰 자사코드·바코드를 붙인다
  칼라명 앞 괄호는 색 계열 수식어라 색 이름이 아니다 — `(핑크&크림)베이지`=베이지, `(인디)핑크&베리`=핑크&베리,
  `(X)내츄럴/그레이`=내츄럴/그레이. 괄호를 떼고 `/ & ·`를 지운 **핵심 색명**으로 비교하면
  온라인 표기와 그대로 맞고(`내츄럴그레이`↔`(X)내츄럴/그레이`, `핑크`↔`(인디)핑크&베리`),
  `핑크`가 `(핑크&크림)베이지`에 걸리던 모호함도 없어진다(`_onsColorCore`).
  원문 정확일치 → 핵심 정확일치 → 핵심 부분일치 순이고, 어느 단계든 후보가 둘 이상이면 비운다.
  탭에 들어갈 때 자사코드가 빈 행만 다시 맞춰 본다(`_onsRefreshMatch`) — 파일을 다시 안 올려도 채워지게.
  **홈쇼핑몰 재고확인처럼 할 일 두 목록**을 요약 아래에 띄운다(검색·필터와 무관하게 전체 기준) —
  `✅ 품절 해제 가능`(`_onsCanFill`: 몰은 품절·일시중단·재고0인데 창고재고 ≥ 기준)과
  `⛔ 품절 처리 필요`(`_onsMustClose`: 몰은 판매중인데 창고재고 < 기준, 창고재고를 모르는 색은 제외).
  기준은 `품절 기준 창고재고 N개 미만`(`onsOutMin`, 기본 30 · localStorage `onsOutMin`) — 홈쇼핑몰의 `hsOutMin`과 따로 둔다.
  창고재고현황을 안 올렸으면 두 목록은 `창고재고현황을 올리면 나옵니다`. 표 마지막 열·엑셀 열 이름은 `할 일`.
  **완료 체크는 홈쇼핑몰과 같다**(팀 공유 `ws/onsStockMarks` = `onsStockMarks`) — 목록 줄의 `✔ 품절 완료`/`✔ 해제 완료`,
  표 상품명 칸의 `전체 품절`(모든 색 몰 품절 + 해제 가능에서 제외). 키는 `몰|자사코드`·`몰|상품명`이라 롯데·현대가 섞이지 않는다.
  파일 그대로의 판정은 `_onsRawOut`, 체크를 반영한 판정이 `_onsIsOut`이다.
  **백화점몰 파일을 새로 올려 몰 상태(판매상태 + 품절 여부, `_onsSig`)가 바뀌면 체크는 저절로 풀린다.**
  두 파일은 **어느 쪽을 먼저 올려도 된다** — 창고재고는 `onsWhPending`(localStorage 전용, 팀 공유 안 함)에
  보관해 뒀다가 백화점몰 파일이 오는 순간 `_onsApplyWh()`로 붙는다. 대조 결과(`rows[].wh`)는 팀에 공유된다.
  화면은 **한 표에 담되 같은 상품명은 `rowspan`으로 셀을 합쳐** 한 덩어리로 보인다(`_onsGroups`).
  열은 `상품명 · 컬러 · 상태 · 창고재고 · 보충여부` 다섯 개뿐 —
  상품코드·자사코드·바코드·현재가·백화점몰 재고수량은 화면에서 빼고 엑셀에만 남긴다(발주에 필요).
  백화점몰 재고수량은 상태 셀 툴팁으로만 보여준다. 표는 `table-layout:fixed`로 열 폭을 고정한다.
  상품 정렬은 보충가능 많은 순 → 품절 많은 순 → 재고 적은 순.
  결과는 팀 공유(`onlineStockDB` / `ws/onlineStock`).
  `📥 몰별 상품리스트`(`onsExportByMall`)는 **매장(몰)마다 시트를 나눠** 내려받는다 — 상품명·컬러·상품코드·자사코드·바코드·몰재고·상태·창고재고·할 일·판매상태·현재가·채널상품코드·스타일코드 13열.
  시트 이름에 못 쓰는 글자(`: \ / ? * [ ]`)는 빼고 31자로 자른다(`_onsSheetName`). 기존 `📥 엑셀`(`onsExport`, 몰 열 포함 한 시트)은 그대로 둔다.

- 백화점몰 재고확인 — **현대백화점(천호) 파일도 받는다**(2026-09 영업2팀): `상품옵션별재고현황_상품옵션별판매가능수량관리_*.xlsx`

  **스타일코드가 없어 판매상품명으로 상품코드를 찾는다**(`_onsCodeByName`) — `(4 colors)`를 떼고 낱말이 모두 든 상품데이터 상품명,
  코드가 여럿이면(성인 `누비아` WLM13I9S ↔ `키즈 누비아` KLS13I1S) 브랜드 괄호·시즌(`26SS`)을 뗀 이름이 **그대로 같은** 것만 고르고, 그래도 여럿이면 비운다.
  색은 `옵션명` `아이보리:Free`의 `:` 앞, 재고는 `남은수량`.
  **매장 단위로 나눈다**(`_onsStoreName`, 행마다) — 롯데 `점포=본점` → `롯데 본점`, 현대 `점명=주식회사 현대백화점 천호점` → `현대천호점`
  (영업2팀 지정 표기: 롯데는 띄어 쓰고 현대는 붙여 쓴다, 그 외 브랜드는 `브랜드 지점점`). 새 매장 파일을 올리면 탭이 저절로 생기고,
  업로드는 **그 파일에 든 매장만** 바꿔 끼운다(`_onsPutMall(rows,fileName)`). 탭 순서는 브랜드(`ONS_MALL_ORDER` 롯데→현대→그 외) 다음 매장 이름순,
  색은 `_onsTone`(롯데 빨강·현대 초록·그 외 청록).
  파일의 점포 표기가 부르는 이름과 다르면 `ONS_STORE_ALIAS`에 한 줄 넣는다(`롯데 아울렛 고양터미널점` → `롯데 고양점`).
  **화면 표기는 `(백)…`**(`ONS_STORE_RENAME`: 롯데 본점→`(백)롯데본점`, 현대천호점→`(백)현대천호`, 롯데 고양점→`(백)롯데고양`)이고
  탭·엑셀에 **매장코드**(`ONS_STORE_CODE`: LTOA·HDOC·LGY)를 함께 적는다. 예전 이름으로 저장된 자료·완료 체크·고른 탭은 `_onsFixMallName`이 옮긴다.
  이름 앞에 `(백)`이 붙어 **브랜드 판별은 `indexOf>=0`·색은 `/롯데/`·`/현대/`** 로 봐야 한다(앞글자 비교로는 못 잡는다).
  파일명에 시각이 없으면(`롯데 고양점.xlsx`) 기준시각은 `…업로드`(올린 시각)로 적는다.
  **스타일코드 뒤에 색 코드가 붙어 오는 상품**(고양점 `PJF40Z9ZIV` = `PJF40Z9Z`+`IV`)은 `_onsResolve`가 뒤를 떼며(8자까지) 상품코드를 찾고
  뗀 꼬리를 색 코드로 먼저 맞춘다. 찾은 상품코드로 `r.code`를 저장해야 창고재고(`상품코드|색코드`) 대조가 된다.
  **같은 색이 사이즈만 다르면**(카밀 옐로우 `S`·`ONE SIZE`) 몰 옵션이 free라 ONE SIZE(`X`)·FREE(`F`) 하나로 정한다.
  예전 이름(`롯데`·`현대 천호`)은 `_onsMigrateMalls`(자료·기준시각)와 `_onsFixMallName`/`_onsFixMarkKeys`(완료 체크·고른 탭)가 옮긴다 —
  팀 자료와 완료 체크가 **따로 도착**하므로 체크 쪽도 받을 때마다 따로 고친다. 옛 `롯데`는 롯데 매장이 하나일 때만 그 매장으로 본다.
  **`일시중단`(옵션·상품 판매구분)도 품절로 본다**(`_onsIsOut`) — 팔 수 없는 상태라서.
  **몰별로 따로 보관한다**(`_onsPutMall`, 행마다 `mall`, 옛 자료는 `롯데`) — 롯데 파일을 올려도 현대 자료는 남고 그 반대도 같다.
  **매장(롯데 본점 · 현대천호점 …)은 탭으로 따로 본다**(`#onsMallTabs`, `onsMallSel`/`onsPickMall`, localStorage `onsMallSel`) —
  고른 매장만 요약·할 일 목록·표에 나오고, 탭마다 색 수·해제가능·품절처리 건수·기준시각을 적는다.
  매장이 둘 이상이면 `전체` 탭이 생기고, 전체에서는 표를 **매장 구역 띠**로 나눈다.
  상품명 칸의 몰 배지, 엑셀 `몰` 열은 그대로.
  묶음 키는 `몰|상품명`이라 롯데·현대 같은 상품이 섞이지 않는다.

- 재고이관 분석 (`🔄 재고이관` 탭): PlayMD **매장재고현황 + 창고재고현황 + 매장판매일보** 업로드 →
  SKU × 매장별 주간 판매속도·재고소진주수(WOS) 계산 → 창고→매장 보충 / 매장 간 이관 / 종료매장 회수 추천,
  무판매·저회전, 월간 전체 점검(사장재고·매장 편중), 엑셀 7시트 다운로드.
  이관 유형은 `창고보충`·`재고이동`·`종료매장 회수` 3가지이고 구분·출발·도착으로 필터할 수 있다.
  조회주수는 판매일보 판매일자에서 **주일 단위**로 자동 산출. 반품은 음수로 상계.
  **부자재 제외**: 창고재고현황 `품목=부자재`인 상품코드, 그리고 이름에
  `쇼핑백/지퍼백/선물박스/더스트백/논우븐/원목/스탠드`가 들어가는 포장·집기류는 분석에서 뺀다
  (창고재고가 0이라 창고재고현황에 안 잡히는 부자재를 이름으로 보조 판별).
  `창고보충 최소재고`(기본 20개)보다 창고재고가 적으면 창고보충을 추천하지 않는다 — 매장 간 재고이동에는 적용 안 함.
  **기준값 기본**(매장 발주 주 2~3회 전제) — 조회 4주 · 목표 재고 1주치 · 공급매장 보유 1주치 ·
  최소 이관수량 0개 · 곧 닫는 매장 제외 2주 · 창고보충 최소재고 20개. 목표=보유 같은 값 허용.
  최소 이관수량 0은 '제한 없음'이고, 실제 이동 수량은 최소 1개로 막는다.
  기준값·설명은 `⚙ 기준값` 버튼으로 접어 두고, 표는 `간단히/자세히` 토글로 열 수를 바꾼다
  (기본 간단히 — 이관 추천은 구분·상품·출발·도착·수량·도착소진 6열, 자세히는 16열. `transferSimple`).
  분석을 마치면 `🏬 매장별` 뷰가 먼저 열린다 — 매장 카드(재고·주간판매·소진주수·받을/보낼/부족)를
  누르면 그 매장의 받을 것·보낼 것·부족한 상품 상세가 펼쳐지고, 다시 누르면 접힌다.
  부족 목록에는 못 채운 이유(최소 이관수량 미달 / 창고재고 부족 / 여유 없음)를 적는다 —
  목표를 낮추면 필요수량이 1~2개로 작아져 최소 이관수량에 막히는 게 대부분이다.
  자주 발주하는데 목표를 높게 잡으면 발주로 채워질 몫까지 창고보충으로 쏟아진다(8주치면 176건, 3주치면 23건).
  **매장 상태는 백화점 탭이 정본** — 거기서 기간이 끝나 퇴점된 매장, 백화점 탭에 없는 매장은 종료로 본다.
  PlayMD와 백화점 탭은 표기가 달라(`롯데백화점 잠실점` vs `롯데 잠실점`) `_tfNormStore`로 정규화해 맞춘다.
  칩 클릭은 이 탭에서만 쓰는 예외 지정(`transferStoreOverride`, localStorage).
  **퇴점 매장은 재고·판매 모두 분석에서 제외**한다 — 지난 매장 데이터는 현 시점에 쓸모가 없다.
  잔여재고는 월간 점검과 엑셀 `퇴점매장재고` 시트에 참고로만 남는다.
  매장명에 `행사/특설/이벤트`가 들어가면 **행사 매장**으로 보고 이관에서 뺀다 — 행사용 한정상품이라 주고받지 않는다.
  백화점 탭 종료일까지 남은 기간이 `곧 닫는 매장 제외`(기본 2주)보다 짧으면 **이관·창고보충 대상에서 뺀다** — 보내도 팔 시간이 없다.
  **팝업 매장은 조회기간 중 일부만 영업**하므로 매장 영업주수는 `조회주수 × (그 매장 판매일수 ÷ 전체 판매일수)`로 비례 산출한다(최소 1주).
  등급은 소진주수 기준이되 26주 초과를 **저회전**(주간 1개 미만, 할인·소진 대상)과
  **과잉재고**(주간 1개 이상, 발주 조정 대상)로 나눈다 — 잘 팔리는 상품이 장기재고로 잡히지 않게.
  무판매는 운영 매장에 깔린 것만 주간 목록에 올리고, 창고에만 잠든 재고는 월간 사장재고로 넘긴다.
  자비스에는 SKU별 매장 판매 이력이 없다 — `dailySalesDB`/`deptDB`는 매출액만이고 판매일보 장바구니는 미저장.
